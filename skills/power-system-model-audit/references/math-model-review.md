# 数学模型核查与文档补全

## 三方证据与复核触发

同时对照原始 TeX/文字、活动代码、独立物理或数学依据。原规范是当前核对对象，不能无条件当作正确答案。触发复核的情况包括单位/量纲矛盾、守恒或边界冲突、公式与推导不符、无法解释的结果、代码与文字不同、双方一样却违反独立关系、代码出现文字未描述的常见关系。

独立依据可为已核实的作者定义、可复算的守恒推导/手算反例、确认过的规范或权威来源。外部资料若用于定级，检索核验原文并记录来源。常识提示只是候选；物理条件须与模型假设相容，不能凭“常见”直接确认为错误。

## 双向清单

逐项记录：关系 ID、模型适用性、文字位置/是否覆盖、活动代码位置/是否实现、变量/单位/索引/开关、独立依据、已验证证据、文字/代码正确性（正确/错误/未知）、候选补全 LaTeX。文字或代码的代数等价、隐含条件先分析，不能用关键词未匹配直接认定遗漏。

| 情况 | 归因与动作 |
| --- | --- |
| 文字错误、代码正确，独立证据充分 | ERROR / MATHEMATICAL_MODEL；给出原式、正确候选、推导/反例及原文位置，不要求代码迎合错误文字 |
| 文字正确、代码错误/遗漏，证据充分 | ERROR / IMPLEMENTATION；给出公式和实现偏差 |
| 文字与代码一致但共同错误 | ERROR / BOTH；以独立关系判断，双方一致不能证明正确 |
| 有差异但独立依据不足/定义不清 | WARNING / REFERENCE_CONFLICT；并列解释和区分工况，不擅自选择一方为真值 |
| 文字未列、代码正确实现适用关系 | WARNING / DOCUMENTATION_GAP；实际撰写公式/文字补全，并报告来源、适用范围和状态 |
| 文字未列、代码也没有 | 两边覆盖缺口；先查隐含等价实现/是否必要，再定级，不假装已有实现 |
| 当前模型不适用该关系 | 不补全；代码若额外施加，复核是否有意扩展或错误收紧 |

## 必须形成的补全内容

在最终 `audit_report.md` 写入可直接合并的文字或 LaTeX 段落：新增编号、完整公式、符号/单位、所有适用集合与初末边界、来源代码行号、原文插入位置、物理/推导依据，以及“代码观察草案 / 在声明假设下已核对 / 待确认修正”等状态。不能只写“建议补上无功平衡”就结束。

补全以代码中的真实表达式和独立核查为依据，不能把错误代码原样升格为规范。它首先是文档补全，不能自动成为确认原代码正确的独立参考。数值结果通过也不等于该关系所有索引/场景都实现正确。

无功平衡示例：确认是 AC 或含 Q 的支路模型，检查 Q 注入/负荷、支路两端方向、并联元件及损耗定义。正文缺省而代码有正确关系时，按实际约定补全 Q 方程及索引；含 shunt 的模型不能用无 shunt 例式替换。纯有功 DC 模型不补入 Q 平衡。类似规则适用于状态域、初末条件、设备界等关系。

## 修改边界与参考版本

默认将补全/修正实文放入报告，保留原文与数值基线。用户已指定修改原 TeX 或授权相应范围时，直接落实修订并在报告记原式→新式、行号和版本，无需重复请求确认；只要求审计或维护skill/Agent时，不默认改动全部原模型和TeX。

原始规范、疑似错误项、候选修订版和当前数值检查基线分别记录哈希。必要时针对候选参考另建并测试检查器，保留原版检查结果；不在原检查器中悄悄替换公式、改旧结果哈希或用补全消除报警。物理定义仍有歧义时可以完成候选实文，状态保持待确认。

## 脚本与 Agent 的分工

`psaudit_review_inventory` 接受经 Agent 审阅的双向清单，确定归因/补全状态；它不自动解析任意 TeX，不自己证明参考正确。`referenceVerified=true` 必须已有依据与可复算证据，不能仅来自“代码能求解”。`textCorrect`/`codeCorrect` 只取 1/0/NaN（未知）。

`psaudit_write_model_review` 将归因和实际补全 LaTeX 写入报告；数字由固定检查器提供，语义映射/数学推导由 Agent 负责。使用前先完成适用性和等价性判断，不能把脚本分类结果当作独立证明。

REFERENCE_CONFLICT下已形成的候选定义也保留实际LaTeX，状态为PROPOSED_DEFINITION；未解决基准、阶段或功率周期时不能因公共报告重构丢失候选实文，也不能把它提升为已确认修正。案例解释放在绑定版本的审阅清单/notes，报告模板只读取本次证据。
