# 报告交付与定级

同时交付[极简简报](../assets/audit-brief.md)和[专业报告](../assets/audit-report.md)，共用本次检查数据与结论。简报链接专业报告；逐模型专业报告配同名 `_brief.md`。无问题时只写“本次已检查范围内未发现需处理问题，暂不需要改正”。新模型由 Agent 直接审计时也须交付两份。专业报告汇总全部入口、归因、数字与补全实文；`psaudit_write_audit_report`从本次entries/findings/witnesses/execution生成日期、数量与表格，并调用`psaudit_write_brief_report`生成简报，不内置案例结论。经审阅的数学解释留在适配器清单并绑定版本。原文修改已授权时记录实际变化，否则给候选；不额外开发JSON/HTML接口。

## 定级与来源

报告覆盖摘要来自[项目关系清单](relation-inventory.md)，列出无card的目标/边界/耦合、未实现、未执行和数据不足项；未完整盘点不写整模型覆盖率。已检查发现违规与模型通过分开表述。

严重性与来源分开：来源为MATHEMATICAL_MODEL、IMPLEMENTATION、BOTH、DOCUMENTATION_GAP、REFERENCE_CONFLICT、NUMERICAL_EVIDENCE、CHECKER或EXECUTION。

- ERROR仅用于独立证据充分的数学错误、实现错误、双方错误或有效数值违规；执行错误单列。原规范有未解决矛盾时不把对其的条件式数值偏离自动确认为代码错。
- WARNING用于文字缺口/补全、规范争议、静态疑点、依据/数据不足、仅数值未激活且无独立证明、无有效解或未证实最优性。独立系数映射和定义已充分证明错误时，不因当前解未激活而降级；表示差异本身不证明非等价。文档遗漏而代码正确不判代码ERROR。
- INFO用于适用范围摘要、关系一致或不适用。
- 每条含ID、来源、原文/源码位置、独立依据、判断状态、实际/期望/残差/单位/阈值/数量，以及补全/修正状态。数值通过不证明代码完整，也不撤销未解决数学争议。


简报只列实际检查文件、可能有问题的位置和是否需要改正，不展开公式、残差、哈希或过程；确认错误写“是”并注明改代码/正文，争议写“先确认”，数据不足写“先补证据”。专业报告保留错误归因、数值证据及数学补全实文。
