# 通用审计方法

## 双输入与覆盖清单

以研究者文字/数学规范定义待核对关系，以源码确定实际实现，以独立物理/数学依据核查双方。原规范必要时也可能有错；触发时按 [数学模型复核](math-model-review.md) 审查，不能单向归咎代码。先列入口→TeX/参数/参考版本/场景/结果依赖，每个入口建立双向清单：变量域、目标、等式、不等式、逻辑/状态、初末条件。报告逐个列出运行失败、参考争议、文档缺口和数据不足。

每项记录 ID、单位/基准、索引集合、活动条件、参考公式、源码位置、实现/验证方式。索引集合来自规范，不从已存在约束的循环范围生成，否则漏掉的末时段也会被检查器漏掉。

每项另外核对“原文有没有写、活动代码有没有做、适用物理依据是否支持”，不只从公式向代码搜索。代码已实现但文字没写全时撰写实际补全公式/段落，并在报告记录DOCUMENTATION_GAP、源码来源和补全状态；常见约束先判断模型适用性。

## 等价性与错误类型

- 向量化、代数消元、表达式覆盖声明变量可以合法；检查实际传入求解器的活动表达式。
- 判断遗漏前检查其他约束是否已蕴含该条件。例如分段上限之和可能已蕴含总出力上限，删除总上限不必造成数学遗漏；必要时通过反例检验。
- 同时核对标幺基准、Δt、MW/MWh、每小时/每时段成本及爬坡率、索引映射、多设备同节点、网络方向与两端功率。
- 不同版本、场景、随机种子或拓扑结果不能混用；旧结果须对应旧输入快照。
- 近似误差、松弛间隙、有限场景覆盖、整数最优性 gap 与实现错误分别报告。

## 固定数值验证

从规范独立推导 actual/expected：等式 abs(a−e)，上界 max(a−e,0)，下界 max(e−a,0)，阈值 absTol+relTol·scale。单位和尺度单独定义；检查全部适用元素，记录最大原始残差、最严重违规位置、位置阈值及计数。整数/二元域通过距离相应集合构造关系。

节点守恒从设备/支路重建，全网汇总直接读设备/负荷，不只是加总同一节点残差。动态设备从独立初值累计递推，不每步用输出状态重新初始化。成本从可信参数和输出决策重算，不复用 obj。

有时间上限但存在可用 incumbent 时可检查可行性，单列未证实最优性。NaN/Inf、缺失变量、维度错误或不允许使用的求解状态为数据不足；不能以空数组当通过。

## 补充场景与冻结检查器

先复用全部已有结果；未激活时用非恒定时序、不对称参数、边界负荷等区分场景。遗漏反例可优化违规量，须与正确参考模型分开；预算到期未激活仍为 WARNING。数值违规排除版本/状态/容差问题并关联源码后才可确认根因。

新适配器开发、规范修改与正式审计分开：先手算测试并固定，再调用。怀疑规范/检查器错误时记录复核请求，不临时改到结果通过。

发现数学模型自身错误时保留原式和基线，按独立证据提出修正、对候选版本另建测试检查器；原文与代码可能共同错误，代码也可能比文字正确。仅版本一致或数值通过不决定归因。

## 可行域双向见证

已有解可行性检查之外，分别寻找：①参考允许而实现拒绝（OVERRESTRICTION）；②参考禁止而实现放行（UNDERRESTRICTION）。例如正确最小开机时间允许恰好4个时段，错误窗口却要求5个；原模型保存的解仍可能全部通过正确约束，不能靠那些解排除过紧。

Agent先审阅参考/源码公式及条件，适配器构造独立两侧关系；`psaudit_evaluate_witnesses`固定成员判断，`psaudit_write_witnesses`写赋值、原/期望值、残差、范围和来源。局部手算只说明所列关系不同；条件性功率周期见证保留其条件，不自动确认原模型代码错误。

完整模型见证须有匹配版本的真实有效解及全部适用参考/实现关系覆盖。无解、时限无incumbent、未知变量或缺失关系仍为DATA_INSUFFICIENT。有限候选没有找到见证不证明可行域等价；冗余/代数等价实现应用控制案例排除误报。
