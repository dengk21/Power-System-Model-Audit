# 疑点驱动诊断与有限修复

## 诊断计划

先使用已有结果和已核查定义。在已有工况未激活疑点、需要区分过松/过紧或缺少费用证据时，形成可审阅计划：疑点ID、基线输入/结果哈希、适用条件、改变的参数与数值、保留不变的参数、预期关系、激活依据和停止条件。计划在新求解前固定；后续调整另列版本并说明原因，不根据测试标签设计正式诊断。

可选测试包括非恒定负荷、容量收紧、爬坡放宽、固定运行轨迹的费用重算和设备重编号。容量/爬坡单调关系要求可行域嵌套、目标和其他输入不变，并使用可靠最优值或有效界。变量顺序变化需同步所有映射，多最优解比较可行性和目标而非逐项相同。

扰动无响应可能来自非活跃变量、冗余关系或等价实现；不可行也可能是合法参数变化。响应大小用于形成诊断，不能代替公式正确性证明。结合冻结独立关系、全部适用索引和完整轨迹成员证据后再定ERROR。改变定义条件后出现故障，不回溯判定原输入错误。

按diagnose模式预先设次数、单次/累计求解时间预算，已有缓存优先。计划、执行失败、未激活与重试均保留。执行入口故障修复不改变检查公式，另存工具版本和失败日志。

## 候选修复

审计结论与修复阶段分开。评测先提交完整审计并冻结，再生成候选副本。一般应用在用户授权的修改范围内执行；原始基线、数据、规范和检查器保持可追溯。

- 已确认实现错误：最小代码补丁，保留原/候选文件、修改理由和哈希。
- 数学表达错而代码正确：修正文档，说明无需改代码。
- 文档遗漏：补完整公式、符号、单位、索引与边界。
- 定义未明：保留候选解释和待确认状态，不自行选择定义修代码。
- 等价或冗余实现：记录证明/条件，不强行补约束。

修复轮数与执行预算由任务确定；课程实验每例最多两轮。失败时仅根据固定验收证据调整候选，保留每轮失败。达到上限仍未通过则停止，保留原版与未通过候选。

## 独立验收

确认修改范围与版本没有变化，候选有有效结果，全部适用独立关系、目标分项、变量域、初末边界通过，完整参考轨迹被候选接纳。同时检查原工况、压力工况和预先固定的额外验收工况。文档修正由原始定义与独立推导审阅；不把数值通过当TeX正确性的自动证明。

psaudit_repair_gate接收经核实的scopeVerified、referenceVerified、hasValidSolution、checks、referenceAccepted、objectiveConsistent、fullCoverage、unresolvedDefinition。它是证据门控，不产生规范或代替Agent审阅；任一门控不足则拒绝或推迟。费用增加/下降幅度不是通用回滚标准，补回约束可合理增加成本。

新数值候选使用[语义重放层](semantic-verification.md)的`psaudit_validate_semantic_candidate`读取已绑定实际结果后再调用门控。冻结输入内声明工况、全部关系ID、形状、单位与容差；不能由候选删检查项或放松容差。参考轨迹先经独立规范验证，再判断其是否被候选排除。成本变化仅展示。确认数值反例即可拒绝，其他未决工况仍保留；无反例但有缺项/休眠表示差异时暂缓，全部通过才接受。真实LP与零求解重放见[示例](../examples/semantic/runbook.md)。

验收通过只适用于声明的工况和参考版本，不证明完整可行域等价。报告分别统计确认错误的修复、文档修正/补全、争议推迟、等价保留及新增求解；不要把不同动作合并成自动代码修复成功率。
